Microsoft · 2023–2026 · Production

Log Intelligence

An internal Microsoft service that learns the normal behavior of Microsoft services from their logs and flags unusual patterns early, before they cause an outage. I owned it end to end, from requirements and architecture through production support.

Problem

Services produce huge volumes of logs, and the early signs of a failure usually show up there before anything breaks. No one can watch those logs by hand at scale, so problems were often found only after a service had already gone down.

Result

Outages detected 75% faster across 70+ teams, new teams onboarded in one day, and 30% less developer effort. Published in the Microsoft Journal of Applied Research: “LLM/SLM Embedding Drift-Based Anomaly Detection for Incident Response” ↗

CS 6220 · Georgia Tech in progress

FocalGuard

Detects when an AI chatbot is confidently wrong, without paying to run many models on every question.

Problem
Common checks ask the same model several times, but a model tends to repeat its own mistakes, so agreement proves little. Running many different models on every query is too slow and costly.
Approach
Choose a small set of models whose mistakes rarely overlap, and add a router that calls them only when the first answer looks unreliable. Each answer comes back with a trust score: accept, flag or abstain.
Impact
Planned scale: ~1.8M answers from 6 open models over ~50K questions, generated on a distributed Ray + vLLM pipeline.

Graduate Research Assistant · Georgia Tech

AI Tutor Insights

Turns students’ conversations with our team’s AI tutor into insights professors can act on.

Problem
Our team built an AI tutor that Georgia Tech students use for their coursework. These chats reveal where students get stuck, but no professor has time to read them all.
Approach
A 7-step LLM pipeline grades and summarizes each student’s conversations, groups similar mistakes across the class, and writes up what it finds as a web report.
Impact
For each homework, professors see the top struggles, the concepts and problems students found hardest, and the common mistakes behind them, so they can adjust lectures and support where it matters most.

CSE 6242 · Georgia Tech

CareerAtlas

Helps job seekers compare cities and roles by what a salary is actually worth after local prices and taxes.

Problem
Salary data is huge and messy, and a raw number hides cost of living and taxes. When no option meets all of someone’s requirements, most tools simply show nothing.
Approach
An 8-stage pipeline cleans 1.4 GB of public H-1B wage filings, maps them to cities and adjusts for prices. A search engine then suggests which requirement to loosen and explains why.
Impact
A custom index answers searches about 135× faster than brute force and runs entirely in the browser. The take-home pay calculator is tested against official tax tables.

Research · IIT Guwahati

Fidelity Extraction of Neural Networks

Fidelity extraction: copying a deployed neural network so it behaves identically to the original, just by querying it.

Problem
Companies treat trained models as valuable property and keep the weights private, exposing only the ability to send an input and read the output.
Approach
Recover the network one layer at a time with an SMT solver, using only input-output queries and no training data. A tool generates the attack code from the network’s structure.
Impact
Achieved exact, functionally identical extraction of medium-sized neural networks.
